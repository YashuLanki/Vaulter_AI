RULES, WHICH MATTER MORE THAN THE FORMAT:

- If a number disagrees with what an earlier report said, check whether the
  CHECK ITSELF changed before treating it as a change in the data:
    git log --oneline -3 -- system/scripts/check_answers.py
  A check that was corrected reports a different number from the same facts, and
  that is the check improving, not the data moving. Say which one it was. If you
  still cannot tell, say so -- but look first.
- Never invent a number or a name. Everything you report comes from what the
  script printed or a file you read. If something could not be checked, say
  "could not check" -- never report it as fine.
- "Has not reported in" is NOT the same as "does not have it installed". A
  machine only appears once its owner opens a conversation. Say which you mean.
- Plain English, for a non-technical reader. Say "the firm's drive", not
  "CORPUS_DIR". Say "file list", not "index".
- Short. If nothing is wrong, the whole report should be under fifteen lines.
  A long report on a quiet day trains the reader to stop reading it.
- Do not change anything, publish anything, or apply any update. You are looking
  and reporting only. Anything that needs doing goes in your "what I would do
  next" list for a person to decide.
